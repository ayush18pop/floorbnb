# Paying with x402 v2 (EIP-3009)

Behaviour is defined by `apps/mcp/src/tools.ts` (paid wrapper), `apps/mcp/src/payments.ts` and `packages/x402/src` (`gate.ts`, `types.ts`).

1. Unpaid call to `quote_protection`, `backtest` or `simulate_gap`: the schema is validated first, then the result is `isError: true` with `structuredContent` = `PaymentRequired`:
   `{x402Version: 2, resource: {url, description, mimeType}, accepts: [{scheme: "exact", network: "eip155:56", asset, amount, payTo, maxTimeoutSeconds, extra: {name, version, assetTransferMethod: "eip3009"}}]}`. The same JSON is in `content[0].text`. With `MCP_HTTP_402=1` the server answers a real HTTP 402; a base64 `PAYMENT-REQUIRED` header is sent either way.
2. Settlement assets on BSC (EIP-3009, 18 decimals, EIP-712 version "1"): USD1 `0x8d0D000Ee44948FC98c9B98A4FA4921476f08B0d` and U `0xcE24439F2D9C6a2289F741120FE202248B666666`. Always use the `asset`, `amount` and `payTo` from `accepts`, never from this file. `amount` is in atomic units (18 decimals): "10000000000000000" = 0.01.
3. Build a PaymentPayload with the user's signer: `{x402Version: 2, accepted: <chosen accepts entry>, payload: {signature, authorization: {from, to, value, validAfter, validBefore, nonce}}}`. `accepted` must match the offered requirement exactly.
4. Retry the same tool call with `params._meta["x402/payment"] = payload` (or HTTP header `PAYMENT-SIGNATURE`, base64 JSON).
5. The server verifies, runs the tool, then settles. If the tool fails (status >= 400) the receipt is released and nothing is settled. Success adds `_meta["x402/payment-response"]` (settle result with transaction hash) and a base64 `PAYMENT-RESPONSE` header.
6. Replay: the EIP-3009 nonce is single-use on chain. Never reuse a payload for a different tool or different params.

Rules for the agent: show tool, asset, amount and payee to the user; get an explicit yes; payee and asset must match the PaymentRequired; stay within any budget the user set; the signature comes from the user's wallet, not from a key you hold. b402 is an optional facilitator, untested live; the client flow is the same.
