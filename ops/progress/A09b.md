# A09b progress (keeper aggregator route)
Branch agent/A09b (from main a09a41a). Owned: apps/keeper, packages/bw3 (small), this file.

## Findings (live, read-only, 2026-10-03, BW3 keys loaded from the shell only)
1. **Quote `amount` is the token's smallest unit (wei).** `10000000000000000000` (10e18) quotes 10 USDT -> 0.0426 NVDAB (LiquidMesh, SWAP);
   `100000000000000000000` scales 10x; `"10"` = 10 wei -> `InsufficientLiquidity`; `"10.0"` -> "invalid amount, must be a positive numeric string within uint256 range".
   BSC USDT and all bStocks are 18-decimal, so `amountIn.toString()` is right. (packages/bw3/scripts/amount-probe.ts)
2. **Quote TTL is between 20 s and 40 s** (quoteId reusable at 20 s, "not found or expired" at 40 s). The keeper quotes and swaps back to back, retries the pair once on "not found or expired", and re-quotes + re-simulates if the calldata is older than 10 s at send time (`aggMaxAgeMs`).
3. **Calldata has a wall-clock deadline** (about quote time + 10 min, a 32-bit word inside the vendor payload). Later than that the router reverts `Route: expired`. Live quotes only execute close to real time.
4. **Router / spender:** `tx.to = approveTarget = 0xB44446b0c8E56988c34f7Ff73Ae904982b5FdDA5` (LiquidMesh, mode SWAP) for 4, 5, 10, 400 USDT and the reverse. The quote's `router` field is a route descriptor (`tokenA--tokenB`), NOT an address: do not compare it to tx.to. The factory constructor allowlist must contain `0xB444...FdDA5` (as router and approveTarget) or the keeper (and the vault) refuse the agg route and use Pancake direct.
5. **Minimum order:** the API did not reject 0.1, 1, 4 USDT from a dummy wallet at quote or swap time (the "Minimum order amount is 5 USD" message is mapped to `MinOrder` in bw3 if it appears). The keeper enforces its own floor: it rejects an agg order under 5 USD before calling swap (buy: amountIn; sell: quoted USDT), and the vault's minTrade (6 USDT) normally sits above it.
6. **No route:** `No valid quote result from any vendor, please retry later` (generic `Bw3Error`) -> keeper falls back to direct.
7. **API simulate endpoint** (`POST /pre-transaction/simulate`) works and returns `{status, failReason, balanceChanges, allowanceChanges}`, but it simulates the raw router tx, so it fails with "BEP20: transfer amount exceeds allowance" for a vault that has not approved yet (the vault approves inside `rebalance`). The keeper therefore simulates the real `vault.rebalance(Swap)` with eth_call, which covers approve, router call and SwapGuard balance deltas. The API simulate is not used.
8. **Fork clock gotcha (matters for tests only):** the vendor's Kipseli adapter reverts `Kipseli swap fail: zero out` when the block clock is ahead of its oracle (any warp, or just the ~40 s fork setup on a slow RPC). The fork test pins the fork clock next to the fork head with `anvil_setTime`. Warping the fork to a Tuesday window (what A09's fixture does) breaks live calldata (`Route: expired`, then Kipseli); use `warp:false`.

## Code
- `apps/keeper/src/agg.ts`: wei doc, `buy` flag, `MIN_AGG_ORDER_USD`, one re-quote on expired quoteId, minReceive >= minOutAgg, tx.to must be on `factory.routerOk` with matching approveTarget (else `AggRejected`).
- `apps/keeper/src/keeper.ts`: `tryAgg()`, agg simulate failure -> falls back to direct and re-simulates, TTL refresh before send. Any quote/vendor/no-route error -> `agg_fallback_to_direct` log + direct route.
- `packages/bw3`: doc comment only, plus read-only probes `scripts/amount-probe.ts`, `scripts/swap-probe.ts`.
- `apps/keeper/scripts/fork-setup.ts`: options `allowAggRouter`, `warp`, env `FLOOR_CONTRACTS_OUT`. `scripts/build-open-window.sh`: TEST-ONLY copy of the contracts (in a temp dir, repo untouched) with the trading window always open, used when the real clock is outside Mon-Fri 15:30-19:30 UTC.
