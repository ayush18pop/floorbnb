## EIP-3009 on BSC (fork checks, 2026-10-03, rpc bsc-rpc.publicnode.com)
Full addresses (ARCHITECTURE.md only had truncated ones; matched by prefix and suffix):
U `0xcE24439F2D9C6a2289F741120FE202248B666666` (proxy, impl `0xbef21313c69c009fd7d9510a8d3a481a32473dfc`),
USD1 `0x8d0D000Ee44948FC98c9B98A4FA4921476f08B0d` (proxy, impl `0x694aa534bdef8ed63244eb902e7914e527891f08`).
USDT and USDC were not checked here (b402 docs say Permit2 only).

Both VERIFIED to expose `transferWithAuthorization`:
- `cast code <impl>` contains selector `0xe3ee160e` = `transferWithAuthorization(address,address,uint256,uint256,uint256,bytes32,uint8,bytes32,bytes32)` for both.
- The bytes-signature overload `0xcf092995` exists on U but NOT on USD1. The code uses the v,r,s overload (works on both).
- `authorizationState(address,bytes32)` returns false on both. USD1 also exposes `TRANSFER_WITH_AUTHORIZATION_TYPEHASH()` = `0x7c7c6cdb67a18743f49ec6fa9b35f50d52ed05cbed4cc592e13b44501c1a2267` (standard EIP-3009). U has no such getter.
- Fork settle test passes for both (fork.test.ts: sign with anvil dev account, settle via SelfFacilitatorClient, balance moved, nonce used, replay refused).

EIP-712 domain, VERIFIED by recomputing the domain separator and comparing with on-chain `DOMAIN_SEPARATOR()`:
| token | name | version | chainId | verifyingContract |
|---|---|---|---|---|

## Decisions
- gate runs the handler before settle (arch steps 5 then 6). Settle failure after a good handler returns 402 and withholds the body. Handler status >= 400 releases the receipt and does not settle.
- Pending after `settleDeadlineMs` (20 s): returns the response with `PAYMENT-RESPONSE {success:false,pending:true}`, receipt `pending`, background settle updates it.
- Self facilitator uses the v,r,s overload because USD1 lacks the bytes overload.
- `ReceiptStore` interface lives in x402 types; db file implements it structurally (no cross-package import). x402 tests import db file by relative path.
