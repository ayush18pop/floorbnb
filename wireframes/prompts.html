01 / User flow

Two ways in: a person, or an agent.

A person sets a floor in the web app. An agent does the same through the MCP server and pays per call with b402. Both end in the same place: a vault contract that belongs to the user. The keeper only triggers rebalances; it can never move funds out.

Person

Landing → wallet → floor → confirm → watch → exit

Deposit USDT, pick a basket of NVDAB, SPCXB and QQQB, pick a floor (90% by default), confirm two transactions, then follow value, floor and cushion until the term ends.

Agent

Discover → quote (402, pay) → unsigned tx → user's wallet signs

The agent calls quote_protection, gets a 402, pays with b402, then calls deposit and receives an unsigned transaction. The user's own Agentic Wallet signs it. Floor never signs for users.

Keeper

Trading window → check drift → swap → log

Mon–Fri 15:30–19:30 UTC only. A normal keeper wallet is primary; a Binance Agentic Wallet holds the same role. After 4 idle hours anyone can trigger a rebalance.

02 / How to generate

Consistency comes from the order and the attachments.

  1. Pick the theme once. Dark is the default here; it reads more "agentic". Use the switch below; every copied prompt follows it. Don't mix themes inside one set.
  2. Generate the three component sheets first (C01, C02, C03). Pick the best result of each, and re-roll until the grid, crosshairs and type look right. They are the style anchor.
  3. Then D01, the landing hero. Attach the brand sheet, the logo and C01–C03.
  4. For every later screen, attach the brand sheet, the logo, C01–C03 and your chosen D01, plus the extra references listed on the screen. Say "match the attached screenshots exactly in grid, type and colour" if a result drifts.
  5. Each copied prompt already includes the shared style block (colours, fonts, sizes, grid, components) followed by the screen's own layout and exact text.
  6. Numbers marked "example" are display values for the mockup, not results. Backtest numbers are real (see floor/CONTEXT.md).
